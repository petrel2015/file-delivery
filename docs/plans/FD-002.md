# FD-002 本地加密包合同

首个已接受基础是 FD-001。新增 pack 和 verify：先只在本地形成可验证加密包，不引入网络。

输出为一个新建的私有目录（0700）：archive.zip、manifest.json、password.txt（各0600）。密码采用系统安全随机源，至少128位熵。JSON只返回秘密文件位置，不返回密码；这是本地文件权限保护，不能抵御同用户或管理员读取。后续FD-003复用此目录以恢复密码；跨设备密钥托管不在本阶段。归档采用WinZip AES256 + DEFLATE，文件名仍可见。

pyzipper 0.4.0作为可选archive extra固定版本，基础plan保持无第三方运行依赖。依据[项目文档](https://pypi.org/project/pyzipper/)，该版修复小文件CRC元数据泄露，默认AES256。控制器已安装pyzipper及7-Zip，验证包含独立7-Zip解密和逐文件hash，不声称所有GUI解压器兼容。

采用新目录拒绝覆盖、私有临时目录构建、验明每个解密内容与原始manifest一致后发布。verify不解压，不写入源文件。权限保护和观察到变化的检测不等于对抗性文件系统快照。

合同及可信检查在派发前冻结。最多初次加一次具体缺陷修复，每次600秒；GLM-5.3 low / 单请求max_tokens8192。历史失败成本按项目累加，未知费用保留null。Codex两轮独立审查上限。外部发送及存储未授权。
