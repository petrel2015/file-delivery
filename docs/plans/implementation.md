# 实施合同与接入计划

日期：2026-09-26。当前进展见 docs/current.md；下文保留初始拆分和冻结规则。

## 已确认产品范围

独立 Python CLI 核心，供 Hermes Skill 及后续 MCP 复用。文件/多文件/目录默认加密打包，每个新交付使用随机密码；七牛 Kodo 首个存储实现；默认返回链接、密码、大小、到期时间；明确收件人时可通过 SMTP 发送，本地联系人别名可配置。SQLite 保存任务状态，秘密独立保护。链接有效期和对象保留期分开。默认值拟为 7 天与 30 天，真实服务约束在接入前核实。大陆下载体验和实际费用另行验证。

## FD-001 执行协议

选择只读预检作为首个小闭环，避免首次派发同时涉及加密库、秘密存储和付费服务。代码尚未编写。

1. Codex 准备控制器所有的 tests/acceptance 检查并冻结 hash；所有合同必选条件必须映射到实际检查，不能只信 Worker 自测。当前仅已命名验证标识，可信测试尚未实现。
2. 派发前冻结基线 SHA、合同指纹、可信测试指纹、允许文件和预算。一次初始调用，普通失败至多一次修复，每次至多 180 秒；不隐式重试或恢复未知调用。额度允许不等于费用为零；框架尚无硬 token/货币上限，不声称已实施。
3. Worker 只改合同显式文件。控制器检查 scope、保存候选提交、执行确定性检查并记录命令、退出码、测试数和输出 hash。Worker 可写单元测试，但不能修改控制器验收。
4. 检查失败只反馈 AC 编号、可复现输入、期望/实际结果和对应证据。保留原合同和测试；一次修复仍失败则交 Codex 判断，不再自动调用。
5. 确定性检查通过后，Codex 对固定 SHA 独立审查，最多两轮；未知结果和升级判断不冒充通过。分别记录审查轮次、调用用量和总成本未知项。
6. 通过后再合并/发布该特性，核对远端 SHA 与 clean tree。候选提交不等于已接受发布。

## 通用入口的最低接入条件

需由 AgentRelay 提供可接收业务项目路径、基线 revision、合同文件、可信测试策略和运行目录的受控入口，而非硬编码租约 fixture。

必须支持：持久化 run/attempt 后再启动；一次初始加一次修复的跨进程预算；明确 GLM-5.3 和当前 Coding Plan 并读回实际执行证据；受控候选 checkout、scope 检查和候选提交保留；冻结测试；真实终态关联；超时/进程清理；未知结果不自动重放；失败调用也保存用量，缺失记 null；固定 revision 的审查记录。

第一版可以由 Codex 人工审查和发布，不要求先建自动调度器或持久 Worker 会话。目录白名单和事后 scope 检查不等于 OS 沙箱，应明确其信任边界。

最初检查的接入缺口现已由 Codex 通过通用入口补齐；固定试验脚本未作为业务执行器。首次真实业务调用超时，未完成 FD-001；证据见 docs/evidence/fd001-first-invocation.json。
