# FD-005 联系人和 SMTP 投递

以FD-004C已接受业务提交0fb7169为基础。合同见contracts/FD-005.json，确定性映射见contracts/FD-005.verification.json；只修改合同内的业务文件，控制器验收与发布记录由Codex持有。

读取既有link-verified交付，核验未到期、未撤销的handoff及AES包/密码，再将链接、密码、大小和到期时间发给一个明确地址。Unicode联系人别名映射为严格ASCII邮箱；配置与密码文件必须私有且无符号链接。固定文本邮件，不支持附件、抄送、自定义模板，也不重新打包、上传、签名或续链。

SMTP分为prepare和submit：prepare完成验证TLS、认证、MAIL/RCPT但不发DATA；在本地持久化sending后才执行DATA。结果不确定时保留unknown，不重发；准备阶段明确失败允许后续显式同key重试。channel-accepted仅表示服务器肯定回复且本地持久化，receipt/read仍为unverified。重复已接受请求返回历史结果，即使原链接后来到期也不重发。

先分类已知SMTP/SSL错误，再把未分类普通OSError映射IO_ERROR；进入durable sending后，一切不确定结果优先为SMTP_UNKNOWN。错误文本、SMTP密码、邮件正文及signed URL不进入普通结果、账本或日志。

验收包括真实fork中断、同key并发、有限锁等待、重复提交、秘密轮换、联系人注入、TLS阶段、私有handoff与包篡改、损坏数据库和安全错误边界。共享FD004B合成存储夹具及所有既有控制器回归一并冻结；测试用例数量不替代独立语义审查。

调用使用用户已授权的当前ZCode Coding Plan，按delivery-policy多次修复；未知执行或连续无验证进展先诊断，保留原run、候选、失败和用量。Worker及控制器只用合成数据；真实七牛/SMTP需用户本地配置路径、测试收件地址和相应外部操作范围，单独保存实际联调证据。
